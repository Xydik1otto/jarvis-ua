# Внесок у jarvis-ua

[English](CONTRIBUTING.md) | [Українська](CONTRIBUTING.uk.md)

## Вітаємо

Це українізований форк [isair/jarvis](https://github.com/isair/jarvis): 100% локального AI-голосового асистента, у якого голосовий конвеєр, десктопний UI, майстер налаштувань і шар LLM-промптів локалізовано українською.

Якщо хочеш зробити внесок у сам Джарвіс (функції, upstream-архітектуру, неукраїнські виправлення), будь ласка, роби це нагорі, у [isair/jarvis](https://github.com/isair/jarvis). Цей форк слідує за upstream і існує, щоб постачати й підтримувати український білд.

## Початок роботи

1. Створи форк цього репозиторію, потім склонуй свій форк:

   ```bash
   git clone https://github.com/<your-username>/jarvis-ua.git
   cd jarvis-ua
   ```

2. Створи віртуальне середовище Python 3.11 (або скористайся допоміжними скриптами в `scripts/`):

   ```bash
   python3.11 -m venv .venv
   source .venv/bin/activate
   pip install -r requirements.txt
   ```

3. Потрібен [Ollama](https://ollama.com): Джарвіс запускає свої LLM локально через нього.

4. Запуск з джерел:

   ```bash
   bash scripts/run_macos.sh    # macOS
   bash scripts/run_linux.sh    # Linux
   pwsh -ExecutionPolicy Bypass -File scripts/run_windows.ps1  # Windows
   ```

## Правила розробки

- **TDD**: спочатку напиши тест, що падає, потім реалізуй виправлення. Тести мають перевіряти **поведінку**, а не деталі реалізації.
- **Специфікації**: кожна зміна коду або точно дотримується spec-файлу `*.spec.md` поруч із кодом, або оновлює цей spec у тій самій зміні. Пошукай пов'язані spec-файли, перш ніж починати будь-яку роботу.
- **Зміни промптів потребують eval-кейсу**: будь-яку зміну LLM-промптів (системні промпти, стимули інструментів, обмеження) треба перевіряти проти релевантного eval-кейсу. Якщо eval для поведінки, яку змінюєш, не існує, спочатку напиши його; він має демонструвати покращення.
- **Стиль комітів**: [Conventional Commits](https://www.conventionalcommits.org/) (наприклад, `feat:`, `fix:`, `docs:`, `test:`, `chore:`).
- **Гілки**: твої фіче-гілки та PR цільуються в типову гілку репозиторію.

## Правила української локалізації

- Рядки, видимі користувачу, українською, неформальне «ти», і **без ем дашів** (замість них використовуй кому, крапку, двокрапку або дужки).
- Коментарі в коді та ідентифікатори британською англійською (наприклад, «colour», а не «color»; «behaviour», а не «behavior»).
- Ніколи не хардкодь мовні шаблони за межами навмисного шару промптів з українською на першому місці: асистент спроєктований підтримувати довільну кількість мов, тож тримай визначення та маршрутизацію мовно-незалежними.

## Тестування

Запусти юніт-набір локально:

```bash
pytest -q -m unit
```

CI працює на `ubuntu-24.04` з Python 3.11 і демоном PulseAudio (headless-ранер не має аудіосервера; тестам, що імпортують `sounddevice`, потрібен запущений PulseAudio перед pytest).

Дві свіжі пастки, які варто знати перед відкриттям PR:

- **pydantic має лишатися `<2.14`** для `mcp 1.13.1`: mcp імпортує внутрішній для pydantic символ, вилучений у pydantic 2.14. CI встановлює свіжі версії залежностей, тож пін, що працює локально, все одно може зламатися в CI, коли транзитивні залежності йдуть уперед; зафіксуй зламану залежність у `requirements.txt` замість оновлення mcp.
- **Не коміть файли з літеральними рядками, схожими на секрети** (наприклад, приклади AWS-ключів у реальному форматі). Сканування секретів GitHub заблокує пуш. Де тестам потрібні такі значення, збирай їх під час виконання з фрагментів; дивись патерн у `tests/test_redact_extended.py`.
