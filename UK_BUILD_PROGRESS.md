### КЛЮЧОВИЙ архітектурний конфлікт: ігри vs резидентна модель
На 8 GB VRAM неможливо тримати qwen 7b (6.25 GB) резидентно і водночас грати — грі потрібна ця VRAM.
Варіанти режиму «гра»:
- Автовиявлення запущеної гри (процес/повноекранність) → `keep_alive: 0` (вивантажити модель з VRAM
  одразу після відповіді) АБО зупинити Ollama-модель; інференс лише on-demand.
- On-demand на CPU (RAM) під час гри (повільніше, ~5-10 ток/с, але GPU вільний для гри).
- Або крихітна модель (1.5-3B) у «ігровому» профілі.
- Whisper вже на CPU (Опція A) — GPU не чіпає. Треба ще прибрати LLM з VRAM під час гри.

## Раунд 2 — прогрес

### Лаунчер `launchApp` [ГОТОВО ✅]
- Новий інструмент `src/jarvis/tools/builtin/launch_app.py` + спека `launch_app.spec.md`.
- Зареєстровано в `registry.py` (`BUILTIN_TOOLS["launchApp"]`).
- Конфіг: нове поле `launch_targets` у `config.py` (дефолт: YouTube, Google).
- Активний config.json: каталог **YouTube, Google, Steam, Spotify** (з укр-аліасами).
- **Безпека:** модель обирає лише `target` з каталогу — не може виконати довільну команду. `query` URL-кодується.
- Резолвер: rapidfuzz (ratio/partial), поріг 78, мовно-незалежний (укр+лат). Запуск: `os.startfile` (Win) / `open` / `xdg-open`.
- Тести: `tests/test_launch_app.py` — **10 passed**.
- Перевірено: «включи музику»→Spotify, «запусти стім»→Steam, «ютуб»→YouTube, «знайди в гуглі»→Google.
- **Як розширити:** додати в `launch_targets` записи `{name, aliases[], command}`.
  Приклади command: шлях до `.exe`, `steam://rungameid/<id>` (конкретна гра), `spotify:`, будь-який `https://...`.

### Персоналізація — явний профіль користувача [ГОТОВО ✅]

- Нове поле конфіга `user_profile` = `{communication_style, goals}` (`config.py`).
- Хелпер `build_user_profile_block(cfg)` у `reply/engine.py` → рендерить блок «The user has set the

  `goals` порожнє — користувач допише під себе.
- Співіснує з вивченою пам'яттю (граф Directives/User + щоденник) — не замінює її, а дає надійний базовий шар.
- Тести: `tests/test_user_profile.py` — 4 passed (порожній→None, лише стиль, стиль+цілі, не-dict безпечно).

- **Як редагувати:** `user_profile.communication_style` / `.goals` у config.json. Голосом теж працює через

### Ігровий режим [ГОТОВО ✅]
- Новий модуль `src/jarvis/game_mode.py`: монітор-потік + `is_active()` + `keep_alive(default)`.
- **Детекція гри:** `psutil` — процес під відомим ігровим коренем (`steamapps/common`, Epic, GOG, Riot, EA…)
  АБО ім'я процесу зі списку `game_process_names`. Клієнти Steam/Epic самі по собі НЕ рахуються.
- **Дія при вході в режим:** друк «🎮 Виявлено гру … — звільняю відеопам'ять» + миттєве вивантаження
  chat/intent моделей з VRAM (`keep_alive:0` до Ollama). При виході — «повертаю швидкий режим» + re-warm.
- **Поки гра активна:** усі виклики Ollama йдуть з `keep_alive:0` (модель вивантажується одразу після
  відповіді). Реалізовано централізовано: `ollama.py chat()` інжектує `0`, `warm_up()` пропускається,
  `intent_judge.py` бере `game_mode.keep_alive("30m")`. Whisper вже на CPU → GPU повністю вільний для гри.
- **Конфіг:** `game_mode_enabled` (true), `game_mode_poll_sec` (5), `game_process_names` ([]).
  Увімкнено за замовчуванням — у config.json нічого додавати не треба.
- **Інтеграція:** монітор стартує в `daemon.py` (друк «🎮 Ігровий режим активний»), зупиняється при shutdown.
- Тести: `tests/test_game_mode.py` — 4 passed (детекція за ім'ям/шляхом, клієнт Steam ≠ гра, keep_alive gating).
  Регресії: config/tools/llm — 27 passed.
- **Компроміс:** перша відповідь під час гри платить холодне завантаження моделі (~кілька секунд),
  бо модель щоразу вивантажується. Це свідомо — пріоритет у гри на VRAM.
- **Як додати гру, яку не ловить авто-детект:** вписати ім'я .exe у `game_process_names` (напр. `["game.exe"]`).
